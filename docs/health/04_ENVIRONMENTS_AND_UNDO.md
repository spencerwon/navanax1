## 1. What carries over

Everything in `docs/04_ENVIRONMENTS.md` §2 (code environments), §4 (branching), §4.1
(commit messages), §5 (promotion gates) and §6 (configuration and secrets) applies
unchanged. This document says what is different for a model with no live data feed,
and it states the undo model that `00 §7` requires.

The health subsystem has **no irreplaceable live data**. That changes the risk profile:
the asset here is not a recording that cannot be re-fetched, it is the *provenance* —
which source, which grade, which decision — and provenance is lost by editing in place,
not by a crash. So the standing rule is different in kind but the same in spirit:

> **Nothing is edited in place.** Parameters, evidence, expectations and decisions are
> superseded by new records that name what they replace.

## 2. Code environments

| Environment | What it is | Writes to |
|---|---|---|
| **LOCAL** | A branch on a developer's or agent's machine | Working tree only |
| **TEST** | CI on every push and pull request: both health self-tests before any install, strict after install, `kb-check`, lint | Nothing |
| **REFERENCE** | The vendored JavaScript engine run under Node to regenerate the golden fixture | `tests/fixtures/health/golden_v1.json`, only on a `MODEL_VERSION` bump |
| **PUBLISHED** | The reference app as a static page (today the Operator's Claude artifact; tomorrow wherever the Operator chooses) | Nothing; it is read-only |

There is no STAGE in the market-data sense because there is no stream to shadow. The
equivalent of a shadow run is the **golden diff**: the new Python output against the
reference fixture, every difference explained.

## 3. Data environments

| Data env | Contents | Mutable? |
|---|---|---|
| **FIXTURE** | `tests/fixtures/health/` — golden trajectories, planted knowledge-base violations, infeasible parameter sets | Yes, it is source code; regenerated by tooling, never by hand |
| **KB** | `src/health/kb/data/` — entities, relations, evidence, verification log, schema | **Append-only.** Supersede, never edit |
| **PARAMS** | `src/health/engine/params.json` | Values change through WF-H-01 only; evidence and grade fields through the curator only |
| **REGISTRY** | `scenarios.py` `validation.expects` | Pre-registered; a change is a superseding record (WF-H-02) |

## 4. Branching

As `docs/04 §4`: `main` protected; `feat/<name>`; `fix/<BUG-ID>`; `exp/<name>` never
merged. Two additions:

- `module/<name>` — a branch that adds one module with its flag **off**. Its pull request is the one `git revert` undoes completely (HREQ-X-03).
- `enable/<name>` — the one-line pull request that flips the flag on. Reverting it turns the module off without removing it.

Commit messages carry `Requirement: HREQ-…`, `Bug:`, `Validated-by: health-rigor-lead`,
and for model changes `Model-version: x.y.z` and `Golden: regenerated`.

## 6. The undo model

The Operator asked for a system that is easy to undo and easy to add onto. These are
the mechanisms, from the smallest unit of change to the largest.

### 6.1 A number

A parameter value is changed by a new value with a new `notes` line naming the old value,
the reason, the date and the source. The git history holds the old row; the notes make
the change readable without git. A value that was calibrated says `calibrated_to:`.

### 6.2 A record

A knowledge-base record (entity, relation, evidence, verification) is never edited. A
correction is a new record; the old one gains `superseded_by` and stays. A disagreeing
source is kept in `conflicts` beside the adopted value, with its own evidence and a note.

### 6.3 An expectation

An expectation is a registered claim. To change it, add a new `expects` row with
`supersedes: <metric as previously stated>` and keep the old row with `status: superseded`.
The harness prints both so a reader can see the history on the surface.

### 6.4 A decision

Every decision that shapes the system is an ADR under `docs/health/decisions/`,
numbered, with Status, Context, Decision, Consequences, and How to undo. An accepted ADR
is never edited; a reversal is a new ADR whose title begins "Supersedes ADR-nnnn".

### 6.5 A module

Every module is registered in `config/health/modules.yaml`:

```yaml
- id: engine-v1
  enabled: true
  owner: health-physiology-modeler
  phase: 0
  paths: [src/health/engine/]
  depends_on: [reference-v1]
  tests: [tests/health_selftest.py]
  adr: ADR-0002
  removal: >
    set enabled: false; delete src/health/engine/ and tests/health_selftest.py and
    tests/fixtures/health/golden_v1.json and tools/health_golden.mjs; remove this entry;
    remove the health_selftest step from tools/gates.py and .github/workflows/ci.yml;
    run tools/gates.py.
```

**Removal recipe (HREQ-X-02).** In order: set `enabled: false` → delete the listed
paths → remove the registry entry → remove the module's gate and CI steps if it has
any → run `tools/gates.py`. If anything else must be touched, the module was not
finished, and that is a Tech Lead finding, not a judgment call.

**Add recipe.** Branch `module/<id>` → ADR → registry entry with `enabled: false` →
code, tests, docs → `tools/gates.py` green → **try the removal recipe on a scratch
branch and confirm gates stay green** → PR → approve → `enable/<id>` PR.

### 6.6 A merge

Each module lands in its own pull request. `git revert -m 1 <merge sha>` is the undo
for the whole module, and it is complete by construction of 6.5.

### 6.7 What cannot be undone, stated plainly

A published claim that a reader has already read. That is why the safety review sits
before publication (WF-H-06), and why a wrong number on a surface is S0a.

## 7. Running things

| Command | What it does | Spends anything? |
|---|---|---|
| `python3 tests/health_selftest.py` | Engine self-test with the stdlib only | No |
| `python3 tests/health_selftest.py --no-skips` | Strict: a skipped test is a failure | No |
| `python3 tests/health_kb_selftest.py --no-skips` | Knowledge-base rules, each with a planted violation | No |
| `PYTHONPATH=src python3 -m health.cli status` | Versions, counts, grade share, expectation statuses (about 3 s; `--fast` skips them), every module's flag, the disclaimer and the validation status last; exits 1 on any contract error | No |
| `PYTHONPATH=src python3 -m health.cli kb-check` | Every contract rule; exit 1 on an error | No |
| `python3 tools/gates.py` | All of the repository's gates including the above | No |
| `node tools/health_golden.mjs` | Regenerate the golden fixture from the JS reference (model changes only) | No |
| open `reference/metabolic-map-v1/index.html` | The V1 app, as published | No |

Nothing in the health subsystem needs a credential, a network connection, or a
background job.

## 8. Configuration

```
config/health/
  base.yaml        tolerances, seeds, Monte Carlo defaults, display rules — every threshold (HREQ-N-06)
  modules.yaml     the module registry (6.5)
```

Every change to either file is a logged change with a rationale in the commit message,
as `docs/00` REQ-N-10 requires.
